# 팀 규칙 (팀원용)

시작하기 전에 이 문서만 읽으면 됩니다. 길지 않습니다.

---

## 1. 내 파일은 어디?

| 폴더 | 무엇 | 건드려도 되나? |
|---|---|---|
| `front/` | 화면 (HTML, CSS, JS) | ✅ 화면 담당 |
| `back/chat/`, `back/config/` | 서버 (Django) | ✅ 서버 담당 |
| `back/src/` | **3차 AI 엔진** | ❌ **읽기만. 수정 금지** (필요하면 종원에게 먼저 말하기) |
| `docs/` | 설명 문서 | ✅ 문서 담당 |
| `.env` | 비밀 키 | ❌ **절대 올리지 않기** |

> 모르겠으면 **일단 멈추고 물어보기.** 엔진을 잘못 고치면 답변 품질이 전부 달라집니다.

---

## 2. 처음 시작하기 (10분)

```bash
uv sync
copy .env.example back\.env
```

그다음 `back/.env`에 키를 채웁니다. (**키는 종원에게 따로 받기. 채팅·메일·깃에 붙여넣지 않기**)

```bash
uv run python back/manage.py runserver
```

브라우저에서 `http://127.0.0.1:8000` → 질문이 되면 성공입니다.

- 인증서 오류(`UnknownIssuer`)가 나면 `uv sync --system-certs`
- 재정렬 모델 파일이 필요하면 종원에게 받기 (용량이 커서 깃에 없습니다)

---

## 3. 작업 방법 (git)

1. **내 브랜치에서만 작업**합니다. (`main`, `Dev`에 직접 올리지 않기)
2. 작게 자주 커밋합니다. (한 번에 몰아서 하지 않기)
3. 올릴 준비가 되면 **내 브랜치 → Dev로 PR**을 만들고, 종원이 확인 후 합칩니다.
4. 합치기 전에 **테스트를 돌립니다.**

```bash
uv run python back/manage.py test chat
```

`OK`가 나와야 합니다. 실패하면 PR을 올리지 않습니다.

**절대 올리면 안 되는 것**: `.env`, API 키, 비밀번호, `back/data/onnx/`(모델), `uploads/`, `db.sqlite3`
(`.gitignore`가 대부분 막아 주지만, 올리기 전에 `git status`로 한 번 더 확인하세요.)

## 4. AI(코딩 도구)로 작업할 때

우리는 대부분 AI로 코딩합니다. 그래서 더 지켜야 합니다.

1. **AI에게 범위를 말하기**: "`front/` 안에서만 수정해 줘. `back/src/`는 건드리지 마."
2. **한 번에 하나만 시키기**: 큰 변경을 한꺼번에 시키면 뭐가 바뀌었는지 모르게 됩니다.
3. **AI가 만든 코드를 실행해서 확인하기**: "됐다고 했어요"는 증거가 아닙니다. 화면에서 직접 눌러 보고 결과(스크린샷)를 남기세요.
4. **AI가 새 파일·새 폴더·새 패키지를 만들면** 올리기 전에 이유를 확인하세요.
5. **키, 비밀번호를 AI 채팅에 붙여넣지 않기.**

## 5. 화면 ↔ 서버 약속 (바꾸면 안 되는 것)

화면과 서버는 아래 약속으로만 연결됩니다. **한쪽이 바꾸면 다른 쪽이 깨집니다.** 바꾸려면 먼저 팀에 알립니다.

- 질문 보내기: `POST /api/chat/` (로그인 필요) — `{"question": "...", "conversation_id": 12}` (`conversation_id`는 이어서 질문할 때만)
- 로그인과 대화 목록: `/api/auth/*`, `/api/conversations/*` (자세한 표는 README 8장)
- 화면의 답변 그리기는 `front/static/js/markdown.js`가 맡습니다. 답변 글은 항상 `textContent`로만 넣고 `innerHTML`은 쓰지 않습니다 (스크립트 실행 방지)
- 받는 이벤트: `stage`, `token`, `sources`, `done`, `error` (자세한 설명은 [README 8장](../../README.md#8-웹-api-규약))

화면 파일(`chat.html`, `chat.css`, `chat.js`)은 얼마든지 꾸며도 되지만, 위 약속만은 지켜야 합니다.

## 6. 문서 담당 안내

제출해야 하는 5가지입니다.

1. 요구사항 정의서
2. 화면설계서
3. 개발된 웹 애플리케이션 (이 저장소)
4. 시스템 구성도
5. 테스트 계획 및 결과 보고서

- 서버 구조가 궁금하면 [바뀐 부분과 설계 설명](CHANGES_AND_DESIGN.md)을 읽으세요.
- **테스트 결과는 직접 해 본 것만** 적습니다. 화면을 눌러 본 시나리오, 입력, 실제 결과, 스크린샷을 기록하세요. 안 해 본 것을 "통과"라고 쓰지 않습니다.
