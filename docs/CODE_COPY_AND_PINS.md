# 코드 복사와 중요 대화 고정

## 사용 방법

- AI 답변의 코드 블록 오른쪽 위에서 **코드 복사**를 누릅니다. 코드 본문만 줄바꿈과 들여쓰기를 유지해 복사합니다.
- 브라우저가 복사를 차단하면 직접 복사할 수 있도록 안내합니다. HTTP 환경에서는 브라우저가 지원하는 경우 복사 대체 방식을 사용합니다.
- 이전 대화의 **⋯ → 대화 고정**을 누르면 ★ 표시와 함께 목록 상단에 나타납니다.
- **⋯ → 고정 해제**를 누르면 원래의 최근 수정순으로 돌아갑니다.
- 고정된 대화끼리도 최근 수정순입니다. 고정 동작 자체는 제목·내용·생성일·수정일을 변경하지 않습니다.
- 고정 상태는 DB에 저장되어 다른 브라우저와 재로그인 후에도 유지됩니다.

## 최초 적용

기존 로그인·대화 DB가 준비된 상태에서, 서버를 종료하고 저장소 최상위 폴더에서 실행합니다.

```powershell
cd back
uv run alembic -c chat/pins_alembic.ini upgrade head
uv run python manage.py runserver
```

화면이 갱신되지 않으면 브라우저에서 Ctrl+F5를 누릅니다.

공용 DB는 담당자 한 명만 적용하고, 개인 로컬 DB는 각자 적용합니다. 실제 DB 마이그레이션은 자동으로 실행하지 않습니다.

팀 규칙에 따라 `back/src/`는 수정하지 않았습니다. 고정 정보는 같은 DB의 `conversation_pins` 테이블에 저장하고,
웹 기능 전용 Alembic 설정 및 `conversation_pins_alembic_version` 버전 테이블로 관리합니다.
기존 `src/db/alembic.ini` 명령으로는 고정 테이블이 생성되지 않습니다.
되돌릴 때는 이전 코드로 전환하기 전에 `uv run alembic -c chat/pins_alembic.ini downgrade base`를 실행합니다.
이는 고정 정보만 삭제하며 대화와 메시지는 유지합니다.

## API

- 기존 `GET /api/conversations/` 응답 항목에 `is_pinned`(boolean)를 추가합니다.
- 목록은 고정 대화 우선이며, 기존 최근 대화 조회 범위 밖의 오래된 고정 대화도 포함합니다.
- `PATCH /api/conversations/<id>/pin/`: `{"is_pinned": true}` 또는 `{"is_pinned": false}`.
- 응답: `{"id": 12, "is_pinned": true}`. 같은 값을 다시 보내도 결과가 동일합니다.
- 로그인 및 CSRF 토큰이 필요합니다. 본인 대화만 변경할 수 있고, 없는 대화와 타인 대화는 모두 404입니다.
- 잘못된 입력은 400, 비로그인은 401, CSRF 실패는 403, DB 오류는 내부 상세를 제외하고 503으로 안내합니다.
- 삭제한 대화의 고정 정보도 제거됩니다.

## 검증

```powershell
uv run python back/manage.py test chat
```

추가 테스트는 메모리 DB에서 고정·해제·재로그인·기존 데이터 보존·소유권·CSRF·잘못된 입력·DB 실패 후 재시도·삭제·마이그레이션을 확인합니다.
브라우저 자동 검증에서는 API와 클립보드를 대체하여 코드 원문 복사, 여러 코드 블록, HTML 안전성,
복사 실패 안내, 스트리밍 중 불완전한 코드 블록, 고정 정렬·새로고침·키보드·재시도를 확인했습니다.
실제 공용 DB와 사용자 OS 클립보드를 사용한 확인은 별도로 진행합니다.
