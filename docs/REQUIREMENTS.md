## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 과제 요구 | LLM을 연동한 내·외부 문서 기반 질의응답 웹 페이지. 프런트는 HTML/CSS/JavaScript, 백엔드는 Django, 클라우드(AWS)에 배포 |
| 서비스 | **CodeClue** — LangChain · LangGraph · MCP를 쓰다 만나는 오류를 글이나 스크린샷으로 올리면, 공식 문서 검색(RAG)과 실시간 도구 조회(MCP)를 근거로 원인과 해결 방법을 알려 주는 질의응답 |
| 해결하려는 문제 | 공식 문서가 방대하고 버전마다 달라서 오류 원인을 찾는 데 시간이 오래 걸린다. 답을 찾아도 근거가 어디인지 알기 어렵다 |
| 3차 대비 변경 | 화면 Streamlit → HTML/CSS/JavaScript, 서버 Streamlit → Django, 로컬 → AWS 배포. 질의응답 엔진(LangGraph · RAG · MCP · 멀티모달)은 3차 코드를 수정 없이 재사용 |

## 2. 사용자와 사용 상황

| 구분 | 설명 |
| --- | --- |
| 주 사용자 | LangChain · LangGraph · MCP로 개발하다 오류를 만난 개발자(학습자 포함) |
| 사용 상황 ① | 터미널에 나온 오류 문구를 그대로 붙여 넣고 원인과 해결 방법을 묻는다 |
| 사용 상황 ② | 오류 화면을 캡처해 올려서(글 없이도) 무엇이 문제인지 묻는다 |
| 사용 상황 ③ | 답을 받은 뒤 꼬리 질문을 하고, 나중에 이전 대화를 다시 열어 본다 |
| 사용 상황 ④ | 패키지의 최신 버전이나 릴리스처럼 실시간 정보를 묻는다 |
| 관리 역할 | 운영자(개발팀)가 서버 상태와 DB를 관리한다. 일반 사용자용 관리자 화면은 제공하지 않는다 |

## 3. 기능 요구사항

우선순위: **상** = 서비스의 핵심, **중** = 사용성·안전, **하** = 있으면 좋음

### 3-1. 질의응답

| ID | 요구사항 | 우선순위 | 상태 | 확인 방법 |
| --- | --- | :-: | :-: | --- |
| FR-01 | 사용자가 질문을 입력하면 답변을 받을 수 있다 | 상 | ✅ | S04 |
| FR-02 | 답변은 한 글자(조각)씩 나타나는 스트리밍으로 전달하고, 처리 단계(검색 중 등)를 보여 준다 | 상 | ✅ | S04, 자동 테스트 |
| FR-03 | 답변에 근거로 쓴 공식 문서의 제목과 링크(출처)를 함께 보여 준다 | 상 | ✅ | S04 |
| FR-04 | 문서에 근거가 없는 질문은 지어내지 않고 근거가 부족하다고 안내한다 | 상 | ✅ (엔진) | S06 |

| FR-06 | 질문 유형에 따라 일반 답변 · 공식 문서 검색(RAG) · 실시간 도구 조회(MCP) · 이미지 분석 경로를 자동으로 고른다 | 상 | ✅ (엔진) | S04, S07 |
| FR-07 | 답변의 마크다운 서식(제목, 목록, 코드 블록, 굵게, 링크)을 화면에 서식으로 보여 준다 | 중 | ✅ | S04 |
| FR-08 | 답변의 코드 블록을 버튼 한 번으로 복사할 수 있다 | 하 | ✅ | S04 |

## 4. 비기능 요구사항

| ID | 구분 | 요구사항 | 상태 | 확인 방법 |
| --- | --- | --- | :-: | --- |
| NFR-01 | 보안 | 로그인 필요한 기능은 서버에서 사용자 번호를 **세션에서만** 가져온다(요청에 담긴 값은 무시) | ✅ | 자동 테스트 |
| NFR-02 | 보안 | 글을 보내는 요청(질문 · 가입 · 삭제 등)은 CSRF 검사를 거친다(실패 403) | ✅ | 자동 테스트 |
| NFR-03 | 보안 | 서버 내부 오류 내용(비밀번호, 경로 등)을 화면에 보여 주지 않는다 | ✅ | 자동 테스트 |
| NFR-04 | 보안 | 답변 안의 스크립트나 위험한 링크가 실행되지 않는다(http/https 링크만 허용, 요소를 직접 만들어 그리는 방식) | ✅ | 브라우저 확인 |
| NFR-05 | 보안 | API 키 · DB 비밀번호 · 접속 키(`.pem`)는 저장소에 올리지 않고 서버의 `.env`에만 둔다 | ✅ | 저장소 점검 |
| NFR-06 | 보안 | 로그인 상태는 서명된 쿠키에 담아 위조할 수 없다. HTTPS에서는 보안 쿠키(`DJANGO_SECURE_COOKIES=1`)를 켠다 | ✅ | 설정 |
| NFR-07 | 입력 검증 | 질문은 최대 4,000자, 이미지 한 장은 최대 10MB, 형식과 개수를 서버에서 검사한다 | ✅ | 자동 테스트 |
| NFR-08 | 성능 | 답변은 스트리밍이라 첫 글자가 나올 때까지의 대기를 줄인다. 서버 시작 후 **첫 질문은 모델 준비 때문에 더 걸릴 수 있다** | 🔄 | 서버 측정 (배포 후) |
| NFR-09 | 사용성 | 처리 중에는 단계 표시로 기다리는 이유를 알 수 있다 | ✅ | S04 |
| NFR-10 | 이식성 | 학원 · 회사 네트워크(보안 장비가 인증서를 바꾸는 환경)에서도 외부 서비스에 접속된다. 인증서 검증은 끄지 않는다 | ✅ | 로컬 확인 |
| NFR-11 | 유지보수 | 화면(`front/`)과 서버(`back/`)를 폴더로 나누고 API 약속으로만 연결한다. 엔진(`back/src/`)은 수정하지 않는다 | ✅ | 저장소 구조 |
| NFR-12 | 신뢰성 | 외부 서비스(AI · DB) 오류는 사용자에게 안내 문구로 보여 주고 서버는 계속 동작한다 | ✅ | 자동 테스트 |
| NFR-13 | 테스트 | 웹 계층 자동 테스트가 통과한다(124개, 2026-11-04 확인) | ✅ | 자동 테스트 |

## 5. 제약 조건과 가정

| 구분 | 내용 |
| --- | --- |
| 기간 | 공식 프로젝트 기간 2026-11-04 ~ 11-05, 발표 11/05 15:00 |
| 기술 | Python 3.12, Django 5.2 LTS, HTML/CSS/JavaScript(프레임워크 없음), 클라우드는 AWS |
| 지식 범위 | LangChain · LangGraph · MCP 공식 문서(3차에서 색인한 Pinecone 인덱스). 그 밖의 주제는 근거 부족으로 답한다 |
| 외부 서비스 | OpenAI(답변 · 임베딩), Pinecone(문서 검색), TiDB Cloud(DB). 서버가 이 서비스들에 접속할 수 있어야 한다 |
| 서버 | EC2 1대. 재정렬 모델과 웜업이 메모리를 쓰므로 4GB급 이상을 가정한다(실측 전 가정) |
| 주소 | 도메인이 없으면 HTTP + IP 주소로 서비스한다(비밀번호가 암호화되지 않는 한계) |
| 3차 코드 | 질의응답 엔진은 수정하지 않는다. 단, DB 계층에 대화 제목 변경 기능이 추가되었다(마이그레이션 `0006`) |
| 3차 DB와 분리 | 4차 전용 데이터베이스(`skn35_4th`)를 쓰며 3차(`skn35_3rd`)와 섞지 않는다 |

## 6. 범위 밖(구현하지 않은 것)

| 항목 | 이유 / 대안 |
| --- | --- |
| 로그인 시도 횟수 제한 | 기간 안에 구현하지 못함. 무차별 대입에 약하다는 한계로 명시 |
| 로그아웃의 서버 측 무효화 | 서명된 쿠키 방식의 한계. 24시간 안에 만료됨 |
| 관리자 화면(사용자 목록, 비밀번호 초기화) | 3차 DB 계층에 기능은 있으나 4차 화면은 없음. 운영자는 DB로 관리 |
| 대화 내용 검색 | 제목 검색만 제공 |
| HTTPS | 도메인이 있을 때만 적용 |
| 문서 범위 확장 · 검색 품질 재평가 | 3차 결과를 인용하며 4차에서 다시 측정하지 않음 |

## 7. 요구사항과 검증의 연결

화면 시나리오(S01~S12)와 자동 테스트가 위 요구사항을 어떻게 확인하는지는 [테스트 계획 및 결과 보고서](TEST_REPORT.md)에 있다. 요구사항 ID 기준으로 연결하며, 직접 실행하지 않은 항목은 통과로 적지 않는다.
