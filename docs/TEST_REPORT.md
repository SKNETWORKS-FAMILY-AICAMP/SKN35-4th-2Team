## 2. 테스트 목적과 원칙

### 2-1. 목적
- 3차 엔진을 웹 서비스로 감싼 부분(로그인 · 스트리밍 · 대화 저장 · 이미지 업로드 · 보안)이 요구사항([요구사항 정의서](REQUIREMENTS.md))대로 동작하는지 확인한다.
- 사용자가 실제로 쓰는 흐름(가입 → 질문 → 꼬리 질문 → 이미지 질문 → 이전 대화 열기)이 AWS 서버에서도 끊기지 않는지 확인한다.

### 2-2. 결과 기록 원칙
- **PASS**: 실제로 실행해 통과 기준을 만족하고 증거(스크린샷, 로그)가 있다.
- **FAIL**: 실행했으나 통과 기준을 만족하지 못했다. 원인과 조치를 적는다.
- **NOT RUN**: 실행하지 않았다.
- **REFERENCE**: 3차 결과를 인용한다.
- **자동 테스트(가짜 응답)와 실제 AI를 쓴 실행 결과를 합쳐서 집계하지 않는다.** 자동 테스트는 엔진과 DB를 가짜로 바꿔 웹 계층의 약속을 검사하는 것이고, AI 답변의 품질을 보증하지 않는다.

## 5. 자동 테스트 (웹 계층)

실행: `uv run python back/manage.py test chat` → **124개 통과** (2026-11-04).

| 영역 | 확인하는 것 |
| --- | --- |
| 질문 스트리밍 | 이벤트 순서(`stage → token → sources → done`), 엔진 오류를 `error` 이벤트로 변환, 예외 내용 비노출 |
| 입력 검증 | 잘못된 JSON · 빈 질문 · 너무 긴 질문 400, GET 405, 대화 번호 검증 |
| 가입 · 로그인 | 아이디 길이 · 비밀번호 영문+숫자 · 아이디와 유사한 비밀번호 거부, 관리자 가입 차단, 로그인 실패 문구 통일, 세션 키 교체, 브라우저 종료 시 만료, DB 오류 비노출 |
| 로그인 필요 | 로그인 없이 401, 사용자 번호는 세션에서만 사용 |
| 대화 목록 · 불러오기 · 삭제 | 본인 것만, 남의 대화 404, 삭제 시 CSRF 검사, DB 오류 비노출 |
| 대화 제목 | 제목 변경(1~100자), 제목 검색(여러 단어 AND, 특수문자 처리) |
| 대화 고정 | 고정 · 해제, 남의 대화 차단, 테이블 미준비 시 안내 |
| 이미지 | 개수 · 크기 · 형식 검증, 이미지만 보내기, 저장된 이미지 보기(본인만, 안전한 헤더), 대화 불러오기에 이미지 포함 |
| 화면 약속 | 템플릿에 이미지 JavaScript가 요구하는 요소가 있는지 |
| 서버 시작 | 모델 준비(웜업) 건너뛰는 규칙, 재정렬 모델 폴더 점검 |

한계: 엔진과 DB를 가짜로 바꾼 시험이라 **AI 답변의 품질, 실제 DB 연결, 화면 모양은 보증하지 않는다.** 이는 4장의 화면 시나리오와 6장의 서버 확인으로 보완한다.
